**Дисциплина:** Информационные системы и технологии в научных исследованиях

**Формат:** индивидуальная демонстрация инструментов командной работы GitHub  
**Дата фиксации отчёта:** 19 ноября 2026 г.

## 1. Цель и исходные данные

Цель работы — организовать управление исследовательским проектом с использованием GitHub: версии исходного кода и данных, план задач, ветвление, Pull Request, Wiki и Discussions.

В проекте применяется **синтетический** набор пользовательских сессий: **3 343 пользователя**, **17 399 сессий** за **61 день** (01.06–31.07.2026). На его основе реализован Streamlit-дашборд с KPI, графиками и фильтрами. Полученные закономерности не характеризуют реальную аудиторию и не подтверждают причинно-следственные связи.

## 5. Оценка эффективности и ограничения

- Создано **6 Issues**; **4 закрыты**, **2 открыты** на дату отчёта.
- Создана канбан-доска с четырьмя статусами.
- PR #7 был открыт **18.11.2026 в 21:01 UTC**, объединён **в 21:21 UTC** (около **20 минут** от открытия до слияния).
- **Независимого code review другим участником не было**. Автор самостоятельно просмотрел изменения; это демонстрирует процесс PR, но не заменяет коллективную проверку.
- Проект содержит автоматические тесты и скрипт валидации. Итоговую ручную проверку и фактические результаты команд следует зафиксировать в Issue #5 перед закрытием.
- GitHub Actions, Git LFS, уведомления и интеграции с внешними системами не настраивались (в методичке они приведены как дополнительные возможности).

Сильная сторона выбранной организации — прозрачная история изменений и разделение неизменяемого исходного CSV, кода анализа и отчётов. Основное ограничение учебной реализации — отсутствие распределённой команды и независимого ревью.

## 6. Заключение

Реализована цифровая инфраструктура исследовательского проекта на GitHub: опубликованы данные и код, созданы задачи и канбан-доска, отработан цикл ветка → коммит → PR → слияние, подготовлены Wiki и Discussion. Это делает проект более понятным и воспроизводимым. Для полного завершения ЛР12 требуется зафиксировать результаты тестирования, завершить проверку документации и приложить реальные скриншоты GitHub; для демонстрации полноценной коллаборации желательно привлечь второго участника к code review.

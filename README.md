# Game User Analytics — исследовательский дашборд

Учебный проект по дисциплине «Информационные системы и технологии в научных исследованиях», лабораторные №10–12. Продолжает ЛР9 по визуализации пользовательской активности.

> **Данные синтетические.** Это учебная модель пользовательской активности, а не телеметрия настоящей игры.

## Цель и вопросы

Цель — исследовать динамику игровой активности и различия по регионам, платформам и каналам привлечения. Вопросы: как меняется DAU; какие сегменты наиболее активны; отличаются ли длительности сессий и частота действий между сегментами?

## Источник и состав

`data/raw/user_sessions.csv`: 17 399 записей, 3 343 обезличенных пользователя, 61 день (01.06–31.07.2026). Датасет сформирован для лабораторных №8–9. Поля: user_id, registration_date, event_date, session_start, session_id, region, platform, traffic_source, session_count, session_duration_minutes, action_count, days_since_registration. Часть характеристик и длительности сессий добавлена синтетически для учебного анализа.

## Запуск

Требуются Python 3.10+ и доступ к терминалу.

```powershell
py -m pip install -r requirements.txt
py scripts/validate_data.py
py -m streamlit run app.py
```

Откройте адрес, который покажет Streamlit (обычно `http://localhost:8501`).

Тесты:

```powershell
py -m unittest discover -s tests -v
```

## Структура

- `data/raw/` — неизменяемый первичный CSV (версионируется)
- `data/processed/` — воспроизводимые результаты очистки, **не коммитятся**
- `analysis/` — расчёты KPI и функции агрегации
- `app.py` — дашборд Streamlit
- `scripts/` — валидация и подготовка данных
- `tests/` — автоматические тесты
- `docs/` — проектная документация, план Issues, заготовки Wiki
- `reports/` — отчёты и итоговая оценка совместной работы
- `results/` — иллюстрации и выгрузки

## KPI и визуализации

Уникальные пользователи, сессии, средний DAU за выбранные дни, средняя длительность сессии. Типы визуализаций: линейный, столбчатый, кольцевая диаграмма, тепловая карта, гистограмма, scatter plot, таблица. Фильтры по периоду, региону, платформе и источнику трафика; каскадность регион → платформа → источник, переключение уровня детализации, сброс категориальных фильтров и экспорт данных.

## Ограничения

Нельзя считать, что графики доказывают причинное влияние платформы или региона на вовлечённость. Сегментные численности уникальных игроков не складываются автоматически, если игроки представлены в нескольких категориях; здесь характеристики каждого пользователя постоянны в данных. Отдельные выводы о причинности потребуют эксперимента.

# CONTRIBUTING — правила участия

1. На каждую отдельную задачу создавайте Issue с целью, критериями готовности и меткой (`data`, `analysis`, `dashboard`, `docs`, `bug`).
2. Создавайте короткую ветку от актуального `main`: `feature/data-collection`, `feature/analysis`, `feature/documentation` или `fix/...`.
3. Давайте коммитам осмысленные сообщения (например, `feat: add DAU trend`), не храните в репозитории пароли и токены.
4. Не изменяйте исходные данные в `data/raw/`: все преобразования должны выполняться скриптом и сохраняться в `data/processed/`.
5. Перед PR выполните `py -m unittest discover -s tests -v` и `py scripts/validate_data.py` и проверьте визуально графики и KPI.
6. Создавайте Pull Request с описанием изменений, ссылкой на Issue (`Closes #...`), шагами проверки и скриншотами. По возможности просите ревью у другого участника.
7. Исправляйте замечания в той же ветке. В `main` сливайте только после проверки; завершённые ветки удаляйте.

Эти правила — проект команды. Пока PR не создан и ревью не выполнено, нельзя заявлять об их фактическом соблюдении.
